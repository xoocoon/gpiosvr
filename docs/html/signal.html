signal module

Base classes for receiving and decoding signals on input GPIOs. Decoded signals are exposed as input events (InputEvent).

To receive and decode signals of a specific type (SignalParameters) on a specific GPIO, a signal iterator (SignalIterator) is used.

A GPIO backend must implement PigpioMinimalApi and PigpioCallbackApi to work with this module.

  • Extension mechanism

  • Configuration classes

  • Main classes

  • Constants and defaults

  • Helper classes

Extension mechanism

Custom signal iterators can be created based on the extension mechanism described for the input module.

Existing extensions are:

  • signal_button for physical buttons

  • signal_ir for infrared protocols (currently only RC6 MCE)

The default implementation of SignalIterator supports signal types with fixed or variable pulse lengths or single edges.

Configuration classes

The signal configuration classes are based on the corresponding classes from the input module.

class gpiosvr.signal.SignalParameters(typeName=None, basePulse_μs=None, tolerancePercentage=None, minEdgeCount=None, basePulseCount=None, preamble_ms=None, postamble_ms=None, codeStartBit=-1, bitOrder=None, edgeEvaluationInterval_ms=None, debounce_μs=None)

Bases: InputParameters

A collection of technical parameters for a signal type, i.e. the expected pulses or edges and how to decode them to scan codes.

Before decoding a signal to a scan code, it is first decoded to a sequence of logical bits.

The default implementation of SignalIterator simply alternates the logical bit with the GPIO level. The value of codeStartBit determines the first bit. The number of bits decoded from the signal, the so called bitCount, is derived from the parameters basePulse_μs, minEdgeCount and basePulseCount. See paramsToBitCount().

basePulseCount: int | None

For a signal type with a fixed pulse length, the number of base pulses that marks the end of the signal. For instance, for a basePulse_μs of 45, and a basePulseCount of 10, a scan code is produced after 45 * 10 = 450 microseconds. Defaults to None.

basePulse_μs: int | None

For a signal type with a fixed pulse length, the base pulse length in microseconds. Defaults to 0.

bitOrder: BitOrder

The bit order to use when translating the logical bits of a signal to a scan code. For instance, if the signal is decoded to a logical bit sequence of 1001101, it is translated to scan code 0x4d if the bit order is MSB_FIRST. By contrast, it is translated to 0x59, if the bit order is LSB_FIRST. Defaults to BIT_ORDER_DEFAULT.

codeStartBit: int | str | None

The first logical bit in the decoded signal. It may be 0, 1 for a fixed logical value. It may also be GPIO_LEVEL (str) for the actual GPIO level of the first edge that marks the start of the signal. Defaults to CODE_START_BIT_DEFAULT.

debounce_μs

The time span in microseconds, within which two edges shall be ignored. Useful e.g. for hardware buttons that may produce high-frequency edges due to mechanical bouncing. May also be used to filter out high-frequency noise on a line. Defaults to DEBOUNCE_μS_DEFAULT.

edgeEvaluationInterval_ms: int | None

The interval in milliseconds in which queued edges are evaluated as fixed or variable-length pulses or individual edges. For bursts of pulses, the value must be high enough to completely queue all edges before evaluating them. However, if too long, the decoding into logical bits and translating them to a scan code could be delayed perceptibly. Lower values result in higher CPU load.

minEdgeCount: int | None

For a signal type with variable pulse lengths or for individual edges, the minimum number of expected edges that marks the end of the signal. Defaults to 0.

postamble_ms: int | None

The duration of “silence” in milliseconds that marks the end of the signal after the previous edge. For instance, if set to 300, the signal is considered “ended” if no other edge has occurred for at least 300 milliseconds since the previous edge. The value must be larger than preamble_ms so no new signal is considered “started” before the current signal is considered “ended”. Defaults to (bitCount + 0.5) * basePulse_μs // 1000.

preamble_ms: int | None

The duration of “silence” in milliseconds that marks the start of a signal on the first edge. For instance, if set to 150, a signal is considered “started” on the first edge after at least 150 milliseconds without any other edge. Defaults to basePulse_μs * 1.5 // 1000.

tolerancePercentage: int | None

For a signal type with a fixed pulse length, the maximum tolerated deviation of basePulse_μs (plus or minus). Specified as a percentage value from 0 to 50. Defaults to TOLERANCE_PERCENTAGE_DEFAULT.

typeName: str

The name of the input type for which the technical parameters are valid.

class gpiosvr.signal.PulseIterator(loop, gpioApi, gpio, params=None, maxBasePulseCount=100, isDebugOutput=False, isTesting=False, msgBuffer=None)

Bases: SyncMixin

An async iterator over pulse events, based on the technical parameters of a signal type.

It is the main class receiving edge callbacks and evaluating them based on technical parameters. The iterator yields instances of PulseEvent that can be interpreted as signals, decoded to logical bits and translated to scan codes.

The iterator lazily sets up the edge callback with its GPIO API on the first iteration. Once started, the iterator runs indefinitely, until aclose() is called.

async onArtificialEdge()

Internal event callback. It is called when an outside requestor has triggered an artificial edge via provokeArtificialEdge().

The implementation is expected to put a corresponding PulseEvent instance into the event queue, then return True to show that the event has been handled.

async onPulseInterruption()

Internal event callback. It is called when the pulse sequence has been interrupted according to the technical parameters.

If the implementation wishes to discard the incomplete pulse sequence, it must return True. If the implementation wishes to append further pulses to the incomplete pulse sequence, it must return False. This is the default.

If the implementation whishes to notify coroutines iterating over PulseEvent instances, it must put an instance of PulsesInterrupted into the event queue, then return True.

async onSequenceEnd()

Internal event callback. It is called when the pulse sequence has completed according to the technical parameters.

The implementation is expected to put a corresponding PulseEvent instance into the event queue, then return True to show that the event has been handled.
