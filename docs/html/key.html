key module

Classes dealing with input event devices under /dev/input/.

  • Core concepts

    • Key press

    • Short and long key press

    • Alternate mode

  • Configuration classes

  • Main classes

  • Constants and defaults

Core concepts

Key press

A key press is a series of events starting when a key is held down and ending when the key is released again.

In between, the key may be repeated periodically. The repeat interval depends on the hardware setup and kernel parameters in the case of a physical keyboard, remote control etc. In the case of artificial key presses generated by the signal_button module, the interval can be set with repeat_ms.

Short and long key press

Whether a key press is considered “short” or “long” depends on the value of longPressRepeatCount.

  • A short press has less than longPressRepeatCount repeat events.

  • A long press has exactly or more than longPressRepeatCount repeat events.

Alternate mode

The handling configuration for a key may specify an alternate handling configuration via altConfig. It replaces the original handling configuration when the alternate mode is on.

The alternate mode is toggled via toggleAltMode(). Toggling is also possible via a handling configuration with an alias value set to one of the members or member names of AltAlias.

The state of the alternate mode can be checked via isAltModeOn.

Note that the input module also features an alternate mode. The latter works at the input level, i.e. alternate input events are reported to the Linux kernel in the first place.

Configuration classes

The following is the JSON representation of an exemplary collection of key handling configurations:

{
  "longPressRepeatCount": 8,
  "KEY_VOLUMEDOWN": {
    "shortPressCommands": [
      [
        "/usr/bin/curl",
        "-s",
        "http://multiroom-1/stepVolume?step=-1"
      ]
    ],
    "longPressCommands": [
      [
        "/usr/bin/curl",
        "-s",
        "http://multiroom-1/setMute?enable=true"
      ]
    ],
    "ledColor": "magenta",
    "isRepeatable": true,
    "altConfig": "KEY_F9"
  },
  "KEY_VOLUMEUP": {
    "shortPressCommands": [
      [
        "/usr/bin/curl",
        "-s",
        "http://multiroom-1/stepVolume?step=1"
      ]
    ],
    "ledColor": "magenta",
    "isRepeatable": true,
    "altConfig": "KEY_F10"
  }
}

Returns:

Return type:

Raises:

ValueError – If keyHandlingDict contains at least one unsupported key.

alias: str | None

An alias or logical name for the key. It may be used as a logical identifier and/or in message texts.

altConfig: str | None

The (key) name of a handling configuration to use instead when the alternate mode is on. It may be an arbitrary str and does not have to reference a key constant in the Linux kernel.

isEnabled: bool | None

If False, any key event for the key name is ignored. Defaults to True.

isRepeatable: bool | None

If True, the commands specified as shortPressCommands may be executed with each repeat event until longPressRepeatCount is reached.

keyName: str

The name of the key for which the configuration is valid. It must start with KEY_ and reference a key constant in the Linux kernel as listed in input-event-codes.h. This does not hold when the name is referenced by an altConfig value, in which case it may be an arbitrary str.

ledColor: str | None

An RGB color. It is used to synchronize an indicator LED with key presses. The color may either be specified as a webcolor name like lime or as a hexadecimal value like #00FF00.

longPressCommands: str | list | tuple | None

A single command or a sequence of commands to execute upon a long key press.

onFailureCommands: str | list | tuple | None

A single command or a sequence of commands to execute if at least one of the commands specified as shortPressCommands produces an error. Only relevant if shortPressCommands is not None.

shortPressCommands: str | list | tuple | None

A single command or a sequence of commands to execute upon a short key press. An individual command is specified as a list or a str, as described for ctlbase.process.CommandExecutor._createProcess().

class gpiosvr.key.KeyServer(iterator, taskMonitor, keyConfigs, ledControl, maxErrorCount=None, msgBuffer=None, isDebugOutput=None)

A server receiving and handling key events.

For each received key event matching a key handling configuration, the following actions are taken:

  • An LED is synchronized with the event, if a LED control is available.

  • The alternate mode is handled.

In essence, a key server wraps a key iterator to provide an ongoing processing loop.

The server writes all occurring key events to a message buffer if available and if isDebugOutput is True. It delegates the actual event handling to handleKeyEvent().

If an LED color is configured for a key and an LED control (PiLedControl) is given, it synchronizes the key presses with the LED.

Furthermore, it toggles the alternate mode upon request and may indicate the change by a blinking LED.
