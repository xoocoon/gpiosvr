Core concepts

Key press

A key press is a series of events starting when a key is held down and ending when the key is released again.

In between, the key may be repeated periodically. The repeat interval depends on the hardware setup and kernel parameters in the case of a physical keyboard, remote control etc. In the case of artificial key presses generated by the signal_button module, the interval can be set with repeat_ms.

Short and long key press

Whether a key press is considered “short” or “long” depends on the value of longPressRepeatCount.

  • A short press has less than longPressRepeatCount repeat events.

  • A long press has exactly or more than longPressRepeatCount repeat events.

Configuration classes

The following is the JSON representation of an exemplary key configuration:

{
  "longPressRepeatCount": 8,
  "KEY_VOLUMEDOWN": {
    "shortPressCommands": [
      [
        "/usr/bin/curl",
        "-s",
        "http://multiroom-1/stepVolume?step=-1"
      ]
    ],
    "longPressCommands": [
      [
        "/usr/bin/curl",
        "-s",
        "http://multiroom-1/setMute?enable=true"
      ]
    ],
    "ledColor": "magenta",
    "isRepeatable": true,
    "altKeyName": "KEY_F9"
  },
  "KEY_VOLUMEUP": {
    "shortPressCommands": [
      [
        "/usr/bin/curl",
        "-s",
        "http://multiroom-1/stepVolume?step=1"
      ]
    ],
    "ledColor": "magenta",
    "isRepeatable": true,
    "altKeyName": "KEY_F10"
  }
}
class gpiosvr.key.KeyHandlingConfig(keyName, typeName=None, shortPressCommands=None, longPressCommands=None, onFailureCommands=None, ledColor=None, isRepeatable=None, altKeyNames=None)

Properties describing the handling of a single key.

__init__(keyName, typeName=None, shortPressCommands=None, longPressCommands=None, onFailureCommands=None, ledColor=None, isRepeatable=None, altKeyNames=None)

Creates a handling configuration for a single key.

Parameters:

  • keyName¶ (str) – The name of the key for which this configuration is valid. It must start with KEY_ and reference a key constant from the Linux kernel as listed in input-event-codes.h.

  • typeName¶ (str | None) – The logical name (str) of the signal type associated with the key. This name in turn may reference an external signal-specific configuration and/or be used in messages.

  • shortPressCommands¶ (str | list | tuple | None) – A single command or a sequence of commands to execute upon a short key press. An individual command is specified as a list or a str, as described for ctlbase.process.CommandExecutor._createProcess().

  • longPressCommands¶ (str | list | tuple | None) – A single command or a sequence of commands to execute upon a long key press.

  • onFailureCommands¶ (str | list | tuple | None) – A single command or a sequence of commands to execute if at least one of the commands specified under shortPressCommands produces an error. Only relevant if shortPressCommands is specified, too.

  • ledColor¶ (str | None) – An RGB color. It is intended for an indicator light associated with the key. The color may either be specified as a webcolor name like lime or as a hexadecimal value like #00FF00.

  • isRepeatable¶ (bool | None) – If True, the commands specified under shortPressCommands may be executed with each repeat event until longPressRepeatCount is reached.

  • altKeyNames¶ (str | None) – One or more names of keys to inject when the alternate key mapping is active on the handling level. They must start with KEY_ and reference key constants from the Linux kernel as listed in input-event-codes.h.

class gpiosvr.key.KeyEvent(type, code, keyNames=None, typeName=None, timestamp_μs=None)

A single key event, i.e. a key held down (DOWN) or released (UP).

A repeat event is simply a DOWN event with a repeatCount greater than 0.

Identifier for a “key down” event.

UP = 0

Identifier for a “key up” event.

Raises:

ValueError – If code is a str starting with KEY_, but a corresponding key constant does not existing in the Linux kernel.

code: str | int

A scan code from some hardware, e.g. from a keyboard key or a remote control button or any other signal received on a GPIO. It may also reference a key constant in the Linux kernel. In summary, it may be given in one of the following forms:

  • A str starting with KEY_, in which case it references the name of a constant in the Linux kernel as given in input-event-codes.h.

  • A str starting with 0x, in which case it is interpreted as a byte sequence in hexadecimal form. It either represents a scan code from some hardware, or the value of a constant in the Linux kernel in its hexadecimal form.

  • Any other str in which case it is interpreted as a byte sequence in the form of ASCII characters. It represents a scan code from some hardware.

  • An int, in which case it is interpreted as a decimal number. It either represents a scan code from some hardware, or the value of a constant in the Linux kernel in its decimal form.

keyHandlingConfig: KeyHandlingConfig

The key handling configuration corresponding to code, if it is already loaded. None otherwise.

keyNames: Iterable

An optional iterable of key names corresponding to code.

timestamp_μs: int

The timestamp of the key event in microseconds since the epoch.

type: int

The type of the key event, i.e. DOWN or UP.

class gpiosvr.key.KeyEventServer(taskMonitor, keysConfig, ledControl, eventDeviceName, eventDeviceWaitTimeout_ms=5000, eventDeviceCheckingInterval_ms=1000, isGrabInputDevice=False, cancelCheckingInterval_ms=100, maxErrorCount=None, altConfig=None, msgBuffer=None, ns=True)

A server receiving and handling key events.

It uses a key event listener to wait for key events as soon serve_forever() is called and until close() is called.

The server logs all occurring key presses to a message buffer and delegates the actual processing to handleKeyEvent().

If an LED color is configured for a key and an LED control (PiLedControl) is given, it synchs the corresponding key events with the LED.

Furthermore, it toggles an alternate key mapping upon request and may indicate the change by a blinking LED.
