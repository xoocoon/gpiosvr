gpio_server executable

  • Features

    • UART

  • Environment variables

  • Arguments

Executable script operating a GPIO server as a daemon.

Features

UART

Sending and receiving data via UART is only supported for Pico devices. That is, a GPIO backend must implement PicodApi.

Environment variables

To use a running pigpiod daemon as a GPIO backend, its endpoint can be set in the environment with the following variables:

  • PIGPIO_ADDR – The host name or IP address of the pigpiod daemon to be used as a GPIO backend. The --pihost argument takes precedence, if present.

  • PIGPIO_PORT – The TCP port of the pigpiod daemon to be used as a GPIO backend. The --piport argument takes precedence, if present.

Arguments

To use a running pigpiod daemon as a GPIO backend, its endpoint can be set with the following arguments:

  • -n | --pihost (str) – The host name or IP address of the pigpiod daemon to be used as a GPIO backend.

  • -p``| ``piport (int | str) – The TCP port of the pigpiod daemon to be used as a GPIO backend.

If using picod daemon and the gpiosvr.picossa module as a GPIO backend on a Pico or Pico 2 device, the following arguments are valid:

  • -u | --picouid (int | str) – The UID (ID_SERIAL) of the target device, either as a 20-digit decimal number or a 16-digit hexadecimal number. It can be obtained by calling uid() on the target device, or by executing udevadm info /dev/ttyACMx | grep ID_SERIAL on the command line, where /dev/ttyACMx represents the target device.

  • --uartconfig (str) – Absolute path or filename (to be auto-detected) for the UART configuration, if one or two UART channels shall be opened.

  • --conncheck (int | str) – The checking interval for the Pico connection in seconds. If, after the specified interval, the Pico target device is recognized as disconnected, the GPIO server is terminated. It defaults to 5 seconds.

The following arguments are independent from the GPIO backend:

  • --signaldebug, --buttondebug, --irdebug (flags) – If present, debug output is written to the log file. The flags correspond to the activity of signal iterators (SignalIterator), button iterators (ButtonIterator) and IR iterators (IrIterator), respectively.

  • --sockdebug (flag) – If present, debug output from the GPIO server’s Unix socket is written to the log file. It mainly includes requests received via the socket and the data written in response.

  • --signalconfig, --buttonconfig, irconfig /str) – Absolute path to a configuration file or a filename for auto-discovery. The arguments correspond to a signal server configuration serving plain signals, button signals and IR signals, respectively.

  • -g | --group (str) – Name of the group to which the GPIO server’s Unix socket shall be accessible.

  • Required positional argument – Absolute path to the Unix socket to be created by the GPIO server.

Additionally, the standard arguments from DaemonControlShell.addStandardArgs are accepted.

Main classes

class gpiosvr.bin.gpio_server.RequestProcessor(taskMonitor, keyInjectors=None, serverVersion=None, backend=None)

A processor parsing and processing requests given as a str.

A sub class may support an arbitrary syntax for requests, but the following commands need to be supported independently of the GPIO backend in use:

key <gpio> <code> or key <gpio> <keyName>
Inject a scan code or key name into a running input iterator or input server, respectively.
<gpio> addresses an input iterator or input server by GPIO number.
<code> is a scan code in hexadecimal form, i.e. starting with 0x.
<keyName> must start with KEY_ and reference a key constant from the Linux kernel as listed in input-event-codes.h.
info
Display information on the GPIO server. The response is a human-readable str.
__init__(taskMonitor, keyInjectors=None, serverVersion=None, backend=None)

Creates a request processor.

Parameters:

  • taskMonitor¶ – See taskMonitor.

  • keyInjectors¶ (list[InputServer] | tuple[InputServer]) – The possible targets for injecting key names or scan codes. In the default implementation, these are input servers.

  • serverVersion¶ (str | None) – A human-readable str for the version of the GPIO server, to be exposed by the info command.

  • backend¶ (BackendType | None) – The type of GPIO backend in use, to be exposed by the info command.

async processRequest(request)

Parses and processes a request given as a str.

The implementation may immediately return None while further processing the request in the background via the task monitor.

The default implementation only supports the key and info commands.

Parameters:

request¶ (str) – The request to parse and process.

Returns:

The response to the processed request. None if the request does not produce a response.

Return type:

str | None

class gpiosvr.bin.gpio_server.UnixSocketServer(loop, serverSocketPath, requestProcessor, group=None, requestBufferSize=256, maxErrorCount=5, msgBuffer=None, isDebugOutput=None)

A server receiving requests from a Unix socket and sending responses back to the Unix socket.

__init__(loop, serverSocketPath, requestProcessor, group=None, requestBufferSize=256, maxErrorCount=5, msgBuffer=None, isDebugOutput=None)

Creates a Unix socket server.

Parameters:

  • loop¶ (asyncio.EventLoop) – The asyncio event loop in which to receive requests and send responses.

  • serverSocketPath¶ (str) – The path to the Unix socket file used by clients to communicate with the server. If the file already exists, it is deleted and re-created upon server start.

  • requestProcessor¶ (RequestProcessor) – The processor for requests received from the Unix socket.

  • group¶ (int | str | None) – The name or numeric ID (gid) of the group to set as the socket file’s group. Defaults to the primary group of the user starting the GPIO server.

  • requestBufferSize¶ (int) – The maximum number of bytes read at once when the Unix socket signals new data. Defaults to SOCKET_REQUEST_BUFFER_SIZE_DEFAULT.

  • maxErrorCount¶ – See maxErrorCount

  • msgBuffer¶ (ctlbase.message.MessageBuffer) – The message buffer to which to write debug as well as warning and error messages.

  • isDebugOutput¶ – See isDebugOutput.

async close()

Closes all client connections and deletes the socket file.

To restart the socket server, initialize() must be called.

async handleClient(reader, writer)

Starts the processing loop for a single client. It blocks until the client disconnects or close() is called.

Parameters:

  • reader¶ (asyncio.StreamReader) – The reader object from which to read the client’s requests.

  • writer¶ (asyncio.StreamWriter) – The writer object to which to send the responses back to the client.

async initialize()

Initializes the socket server but does not start serving yet.

That is, the socket file is created with the correct permissions and the server object is prepared for serving.

async serve_forever(isDebugOutput=False)

Starts the processing loop and blocks until close() is called or the maximum number of errors is exceeded.

If the socket server is not yet initialized, initialize() is called implicitly.

errorCount

The number of errors that have occurred so far. It is matched against maxErrorCount.

isDebugOutput

If True, debug messages are written to a message buffer, if available. Defaults to None.

maxErrorCount

The maximum number of errors that, if exceeded, leads to a shut down of the server. Defaults to 5.

Constants and defaults

gpiosvr.bin.gpio_server.SOCKET_REQUEST_BUFFER_SIZE_DEFAULT = 256
gpiosvr.bin.gpio_server.SOCKET_REQUEST_MAX_CHAR_COUNT = 256

The maximum number of characters allowed in one request to the Unix socket server. This is intended as a security measure.
